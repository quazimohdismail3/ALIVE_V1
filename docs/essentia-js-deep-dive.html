01 — Foundation

What Essentia.js Is (And Isn't)

What it IS

  • C++ Essentia library compiled to WebAssembly via Emscripten
  • Runs 100% in-browser — no server, no API calls, no latency
  • 100+ music analysis algorithms (tempo, key, pitch, chroma, timbre...)
  • TensorFlow.js bridge for pre-trained deep learning models
  • AudioWorklet integration for real-time stream analysis
  • Web Worker support for non-blocking offline analysis
  • TypeScript typings included
  • npm package + CDN available

What it ISN'T

  • NOT a music player — it analyzes audio, doesn't play it
  • NOT a metadata service — doesn't know artist/title/lyrics
  • NOT stable API yet — backwards compatibility not guaranteed
  • NOT instant for long files — WASM has startup overhead
  • NOT perfect for real-time BPM on live streams (needs 10–30s buffer)
  • NOT a Spotify replacement for catalog/playback
  • AGPLv3 — copyleft license, SaaS implications
🔑

Why This Matters for Mission Alive

Spotify deprecated audio-features + recommendations API in Nov 2024 for new apps. Essentia.js can extract the exact same features (BPM, key, mode, energy proxy, valence proxy, danceability) from any audio buffer in the browser — no Spotify API needed. This is your Spotify audio-features replacement.

04 — Machine Learning Models

Pre-Trained Models — All Available

These run via TensorFlow.js. Input is always pre-extracted audio embeddings (VGGish, MusiCNN, or EffNet). Two stages: embed → classify/regress.

⚠️

Two-Stage Pipeline Required

Models do NOT take raw audio. You must first extract embeddings using EssentiaTFInputExtractor (which computes mel-spectrograms and runs them through a backbone model like MusiCNN), then feed those embeddings to the classifier/regressor. This adds ~200–800ms overhead per track.

Mood Models — Mission Alive Priority

deam-audioset-vggish-2
Arousal + Valence Regression (continuous)
Returns [arousal, valence] as continuous values. Range: 1–9 (normalize to 0–1). Trained on DEAM dataset (1000 clips rated by humans). Most directly maps to Mission Alive's affect_arousal / affect_valence.
→ affect_arousal → affect_valence
emomusic-msd-musicnn-2
Arousal + Valence Regression
Trained on emoMusic (744 clips × 30s). Returns continuous arousal/valence. Backbone: MusiCNN trained on Million Song Dataset. Often more accurate for popular music than DEAM.
→ affect_arousal → affect_valence
muse-msd-musicnn-2
Arousal + Valence Regression
Trained on MuSE dataset. Best generalization across diverse music genres. Use as ensemble vote with deam + emomusic for most robust estimate.
→ affect_arousal → affect_valence
mood_relaxed-discogs-effnet-1
Binary: relaxed / not relaxed
P(relaxed) score (0–1). Use as fast filter: reject tracks with P(relaxed) < 0.4 for INTEGRATE phase. EffNet backbone = best accuracy for music classification.
→ INTEGRATE filter
mood_aggressive-discogs-effnet-1
Binary: aggressive / not
P(aggressive) score. Hard reject: if P(aggressive) > 0.3 for any session type. Aggressive tracks contradict parasympathetic goals.
Hard reject filter
mtg_jamendo_moodtheme-discogs-effnet-1
Multi-label: 56 mood/theme tags
Returns probability for each of 56 tags including: calm, happy, energetic, melancholic, relaxing, uplifting, meditative, atmospheric. Rich classification. Use for session type matching.
→ session type filter

Energy + Engagement Models

danceability-discogs-effnet-1
Binary: danceable / not
P(danceable). High score = strong rhythmic pulse = high rhythmic_complexity. Invert for calm sessions.
→ rhythmic_complexity
approachability-discogs-effnet-1
3-class: approachable
Mainstream accessibility. Low approachability = experimental/harsh = filter out for therapy contexts.

engagement-discogs-effnet-1

Predicts whether a track engages listeners. High engagement during ENTRAIN phase helps hook users. Moderate during INTEGRATE.
→ session engagement

The Embedding Backbone Models

🏗️

Best Backbone for Mission Alive: discogs-effnet

Three backbone choices: VGGish (generic audio, fast), MusiCNN (music-specific, slower), Discogs-EffNet (trained on 500K Discogs tracks, most competitive on downstream music tasks). Use EffNet for mood/valence/arousal. Use MusiCNN when EffNet model not available. VGGish as fallback only.

05 — Real-Time Analysis

AudioWorklet Pattern — Step by Step

Real-time analysis runs on the audio rendering thread via AudioWorklet. Essentia WASM loads inside the worklet. Features extracted every audio frame (128 samples = ~3ms at 44.1kHz).

Setup: Install and Import

Create the AudioWorklet Processor File

This file runs on the audio rendering thread. It imports Essentia WASM and extracts features per frame.

// public/essentia-worklet.js
// Must be a static file — not processed by Vite bundler

import { EssentiaWASM } from 'https://cdn.jsdelivr.net/npm/essentia.js@0.1.3/dist/essentia-wasm.es.js';
import Essentia from 'https://cdn.jsdelivr.net/npm/essentia.js@0.1.3/dist/essentia.js-core.es.js';

let essentia = new Essentia(EssentiaWASM);

class EssentiaWorklet extends AudioWorkletProcessor {
  constructor() {
    super();
    this._sampleRate = sampleRate; // global in worklet
    this._buffer = []; // accumulate frames for BPM analysis
    this._frameCount = 0;
  }

  process(inputs) {
    const input = inputs[0];
    if (!input || !input[0]) return true;

    const frame = input[0]; // Float32Array, 128 samples
    this._buffer.push(...frame);
    this._frameCount++;

    // Extract RMS every frame (instant)
    const vec = essentia.arrayToVector(frame);
    const { rms } = essentia.RMS(vec);
    vec.delete(); // CRITICAL: always free WASM memory

    // Extract BPM every 10 seconds (~430 frames at 44.1kHz)
    if (this._frameCount % 430 === 0 && this._buffer.length > 441000) {
      const signal = essentia.arrayToVector(new Float32Array(this._buffer));
      const { bpm, confidence } = essentia.RhythmExtractor2013(signal);
      signal.delete();
      this._buffer = this._buffer.slice(-220500); // keep last 5s
      this.port.postMessage({ type: 'bpm', bpm, confidence });
    }

    // Post RMS every 10 frames (~30ms)
    if (this._frameCount % 10 === 0) {
      this.port.postMessage({ type: 'rms', rms });
    }

    return true;
  }
}

registerProcessor('essentia-worklet', EssentiaWorklet);public/essentia-worklet.js

export class EssentiaAnalyzer {
  constructor() {
    this._node = null;
    this._ctx = null;
    this._onFeatures = null;
  }

  async init(audioContext, onFeatures) {
    this._ctx = audioContext;
    this._onFeatures = onFeatures;
    await audioContext.audioWorklet.addModule('/essentia-worklet.js');
    this._node = new AudioWorkletNode(audioContext, 'essentia-worklet');
    this._node.port.onmessage = (e) => onFeatures(e.data);
    return this._node;
  }

  connectSource(sourceNode) {
    // sourceNode can be microphone, Tone.js master, etc.
    sourceNode.connect(this._node);
    // Don't connect to destination — analyzer doesn't output audio
  }

  disconnect() {
    this._node?..disconnect();
  }
}

06 — Offline Track Analysis

Full Track Feature Extraction (Web Worker)

Use this to pre-analyze any audio track before queuing it. Returns all 9 Mission Alive-relevant features. Runs in ~300–800ms per track on modern hardware.

// frontend/src/audio/track_analyzer.worker.js

importScripts('https://cdn.jsdelivr.net/npm/essentia.js@0.1.3/dist/essentia-wasm.umd.js');
importScripts('https://cdn.jsdelivr.net/npm/essentia.js@0.1.3/dist/essentia.js-core.umd.js');

const essentia = new Essentia(EssentiaWASM);

async function analyzeTrack(audioBuffer) {
  const sr = audioBuffer.sampleRate;
  const raw = audioBuffer.getChannelData(0); // mono

  // Pre-process
  let signal = essentia.arrayToVector(raw);
  signal = essentia.DCRemoval(signal).signal;
  signal = essentia.EqualLoudness(signal, sr).signal;

  // ── RHYTHM ──────────────────────────────────────────────────────
  const rhythm = essentia.RhythmExtractor2013(signal, sr);
  const bpm = rhythm.bpm;
  const bpm_confidence = rhythm.confidence;
  const beats = essentia.vectorToArray(rhythm.ticks);
  rhythm.ticks.delete(); rhythm.bpmEstimates.delete();

  const danceResult = essentia.Danceability(signal, 2, 8800, sr, 1.5);
  const danceability = danceResult.danceability;

  // ── TONAL ────────────────────────────────────────────────────────
  const keyResult = essentia.KeyExtractor(signal, true, 4096, 4096, 12, 3500, 60, 25, 0.2, 440, 10000, 3500, sr);
  const key = keyResult.key;       // e.g. "C", "F#"
  const scale = keyResult.scale;   // "major" | "minor"
  const key_strength = keyResult.strength; // 0–1, use as confidence
  const key_mode = scale === 'major' ? 1 : 0; // maps directly to MA param

  // ── SPECTRAL (frame-based) ────────────────────────────────────────
  let brightnessSum = 0, roughnessSum = 0, warmthSum = 0, frameN = 0;
  const frames = essentia.FrameGenerator(signal, 2048, 1024);

  for (let i = 0; i < frames.size(); i++) {
    const windowed = essentia.Windowing(frames.get(i), true, 0, 'hann', true, 2048);
    const spectrum = essentia.Spectrum(windowed.frame, 2048);
    const peaks = essentia.SpectralPeaks(spectrum.spectrum);

    // Brightness = spectral centroid
    const centroid = essentia.Centroid(spectrum.spectrum, sr / 2);
    brightnessSum += centroid.centroid;

    // Roughness = perceptual dissonance
    if (peaks.magnitudes.size() > 1) {
      const diss = essentia.Dissonance(peaks.frequencies, peaks.magnitudes);
      roughnessSum += diss.dissonance;
      diss.frequencies?..delete();
    }

    // Warmth = relative energy in Bark bands 0–5 (bass region)
    const bark = essentia.BarkBands(spectrum.spectrum, 24, sr);
    const barkArr = essentia.vectorToArray(bark.bands);
    const totalE = barkArr.reduce((a, b) => a + b, 0);
    const bassE = barkArr.slice(0, 5).reduce((a, b) => a + b, 0);
    warmthSum += totalE > 0 ? bassE / totalE : 0;
    bark.bands.delete();

    // Cleanup WASM vectors every frame — critical for memory
    peaks.frequencies.delete(); peaks.magnitudes.delete();
    spectrum.spectrum.delete(); windowed.frame.delete();
    frameN++;
  }

  const brightness = brightnessSum / frameN;
  const roughness = roughnessSum / frameN;
  const warmth = warmthSum / frameN;

  // ── SILENCE ──────────────────────────────────────────────────────
  const dynC = essentia.DynamicComplexity(signal, 2048, sr);
  const silence_ratio = 1 - dynC.dynamicComplexity; // invert: low complexity = high silence

  // ── CLEANUP ───────────────────────────────────────────────────────
  signal.delete();

  return {
    bpm: Math.round(bpm),       // 60–180
    bpm_confidence,               // 0–1, reject if < 0.5
    key,                          // "C", "G#", etc.
    scale,                        // "major" | "minor"
    key_mode,                     // 0 | 1 (maps to MA param)
    key_strength,                 // 0–1
    danceability,                 // 0–1
    brightness,                   // 0–1 (normalized centroid)
    roughness,                    // 0–1 (dissonance mean)
    warmth,                       // 0–1 (bass energy fraction)
    silence_ratio,                // 0–1
  };
}

self.onmessage = async (e) => {
  try {
    const features = await analyzeTrack(e.data.audioBuffer);
    self.postMessage({ status: 'ok', features, trackId: e.data.trackId });
  } catch (err) {
    self.postMessage({ status: 'error', error: err.message, trackId: e.data.trackId });
  }
};track_analyzer.worker.js
💡

Memory Management Is Critical

Every WASM vector must be manually freed with .delete() after use. Forgetting this causes memory leaks that crash the browser tab after 10–20 analyses. Use try/finally blocks in production to guarantee cleanup.

08 — Mission Alive Integration

Where Essentia.js Lives in the App

Essentia.js Touch Points in Mission Alive

Touch Point 1 — Pre-Session Track Validation

When user picks a track (from curated playlist or their library), run offline analysis via Web Worker before queuing. Check: BPM matches target ± 15%, instrumentalness proxy (low vocals = high HPCP flatness), roughness < 0.5, key_mode matches target. Reject and auto-pick next if criteria fail.

File: frontend/src/audio/track_validator.js (new)

Touch Point 2 — Live Arousal/Valence from Playing Audio

ML model pipeline running every 3s on currently playing audio (via AudioWorklet + Worker). Outputs affect_arousal + affect_valence from audio content. Feeds into ISO bridge as a second source of affect signal alongside HRV. Weighted: HRV 70%, audio_ML 30%.

File: frontend/src/audio/affect_inferencer.js (new)

Touch Point 3 — Post-Session Playlist Analysis

After session ends, batch-analyze top 20 candidate tracks for next playlist. Run offline in background Worker. Cache features in localStorage. On next session start, features are pre-computed. No blocking, no wait.

File: frontend/src/audio/playlist_cache.js (new)

Touch Point 4 — Loudness Normalization

All external music must be normalized to the same perceived loudness before mixing with Mission Alive's stems. Use LoudnessEBUR128 to measure track loudness (in LUFS). Apply a gain correction so all tracks hit −16 LUFS target (matches streaming standard). Essential for hybrid mode.

Runs inside track_validator.js

09 — ML Inference Code

Full Arousal/Valence Prediction Pipeline

Two-worker pattern: Worker A extracts mel-spectrogram embeddings (CPU-heavy), Worker B runs TensorFlow.js inference (GPU via WebGL).

// frontend/src/audio/affect_inferencer.js
// Runs on main thread — coordinates two workers

import { EssentiaWASM } from 'essentia.js';
import { EssentiaModel } from 'essentia.js/dist/essentia.js-model.umd.js';

export class AffectInferencer {
  constructor() {
    this._extractorWorker = null;
    this._inferenceWorker = null;
    this._onResult = null;
    this._ready = false;
  }

  async init(onResult) {
    this._onResult = onResult;

    // Worker 1: mel-spectrogram extraction (Essentia WASM)
    this._extractorWorker = new Worker(new URL('./embed_extractor.worker.js', import.meta.url));

    // Worker 2: model inference (TensorFlow.js)
    this._inferenceWorker = new Worker(new URL('./mood_inference.worker.js', import.meta.url));

    // Chain: extractor → inference
    this._extractorWorker.onmessage = (e) => {
      this._inferenceWorker.postMessage({ type: 'infer', embeddings: e.data.embeddings });
    };

    this._inferenceWorker.onmessage = (e) => {
      if (e.data.type === 'ready') { this._ready = true; return; }
      if (e.data.type === 'predictions') {
        const { arousal, valence, moods } = e.data;
        onResult({ arousal, valence, moods });
      }
    };

    // Wait for model to load
    await new Promise((res) => {
      const orig = this._inferenceWorker.onmessage;
      this._inferenceWorker.onmessage = (e) => {
        if (e.data.type === 'ready') { this._ready = true; res(); }
        orig?.(e);
      };
    });
  }

  analyze(audioSignal) {
    if (!this._ready) return;
    this._extractorWorker.postMessage({ type: 'extract', audio: audioSignal }, [audioSignal.buffer]);
  }
}

  self.postMessage({ type: 'ready' });
});

const MOOD_TAGS = ['aggressive', 'calm', 'energetic', 'happy', 'melancholic', 'relaxing', 'uplifting']; // subset

self.onmessage = async (e) => {
  if (e.data.type !== 'infer') return;
  const emb = e.data.embeddings;

  // Arousal/Valence: outputs [arousal, valence] in range 1–9
  const avTensor = tf.tensor(emb.features).expandDims(0);
  const avPred = avModel.predict(avTensor);
  const [rawA, rawV] = await avPred.data();
  const arousal = (rawA - 1) / 8; // normalize 1–9 → 0–1
  const valence = (rawV - 1) / 8;
  avTensor.dispose(); avPred.dispose();

  // Mood tags
  const moodTensor = tf.tensor(emb.features).expandDims(0);
  const moodPred = moodModel.predict(moodTensor);
  const moodData = await moodPred.data();
  moodTensor.dispose(); moodPred.dispose();

  self.postMessage({ type: 'predictions', arousal, valence, moods: Array.from(moodData) });

10 — Gotchas & Limitations

What Will Bite You

💣

Memory Leak — .delete() Everything

Every WASM Vector/Array returned by an algorithm must be manually freed with .delete(). JS garbage collection doesn't touch WASM heap. Forgetting even one per frame will crash the tab within minutes. Use try/finally. Always.

🐌

BPM Needs 10+ Seconds

RhythmExtractor2013 needs at minimum 10s of audio for reliable BPM. For 30s previews: extract from the 10–25s window (middle section = most representative). Don't run on the first 5 seconds of a track.

🔒

CORS — Cannot Analyze External Audio URLs

Essentia.js decodes audio via AudioContext.decodeAudioData. Fetching audio from Spotify CDN or any external URL will fail with CORS unless the server sends proper headers. Workaround: use Spotify Web Playback SDK (which handles its own auth) and capture via AudioWorklet — but that only works if SDK exposes audio node, which it doesn't. Solution: analyze from pre-loaded buffer only.

📄

AGPLv3 License — Read This

AGPLv3 is copyleft. If you use Essentia.js in a web service (Mission Alive = SaaS), you must open-source your code or obtain a commercial license. UPF offers commercial licenses — contact mtg.upf.edu. Do this before launch.

🔊

No Stereo Width Algorithm

spatial_width param in Mission Alive can't come from Essentia.js — there is no stereo analysis in the current WASM build (it only handles mono). Apply spatial_width via Tone.js StereoWidener post-processing, as it already does.

🎯

Valence Accuracy Is Lower Than Arousal

All MER (Music Emotion Recognition) research confirms: arousal prediction (R²~0.7) is significantly more accurate than valence (R²~0.4). Valence is culturally contingent. Use Essentia arousal predictions with higher confidence than valence. Cross-validate valence with HRV-derived affect_valence.

⚡

WASM Bundle Size ~12MB

The essentia-wasm file is ~12MB. Load it asynchronously in a Worker (not main bundle). Use dynamic import inside the worker. Don't block session start on WASM load — initialize in background while user is on the session setup screen.

✅

Vite: Disable Optimization for WASM

Add optimizeDeps: { exclude: ['essentia.js'] } to vite.config.js. Vite's dep optimizer breaks WASM dynamic loading. Also requires COOP/COEP headers for SharedArrayBuffer if using AudioWorklet.

11 — Build Order

What to Build First, Second, Third

Step 1 — Offline Track Analyzer (1 week)

Build track_analyzer.worker.js as standalone. Test on 10 tracks manually. Verify BPM accuracy vs Spotify's (±3 BPM = pass). Verify key/mode accuracy. This is the Spotify audio-features replacement. No UI needed yet.

Step 2 — Track Validator for Curated Playlists (3 days)

Pre-analyze the 9 curated ISO playlists. Store features in public/playlist-features.json. Ship this file with the app. Zero runtime analysis needed for curated content. Use worker only for user's own library.

Step 3 — Loudness Normalization (2 days)

Wire LoudnessEBUR128 into session_audio.js. Before any external track mixes with stems, compute its LUFS. Apply GainNode correction to hit −16 LUFS target. This prevents jarring volume jumps when Spotify track changes.

Step 4 — ML Mood Models (2 weeks)

Download DEAM + emomusic models from essentia.upf.edu/models. Host in public/models/. Build affect_inferencer.js. Test: analyze a known "sad" track, verify valence < 0.4. Analyze a known "energetic" track, verify arousal > 0.7. Then wire into ISO bridge as secondary affect source (30% weight).

Step 5 — Real-Time BPM Tracking (1 week)

Build essentia-worklet.js. Connect to Tone.js master output via AnalyserNode tap. Track live BPM of whatever is playing (stems or Spotify). Use to verify ISO bridge is working: binaural tempo should track towards target BPM over session arc.
