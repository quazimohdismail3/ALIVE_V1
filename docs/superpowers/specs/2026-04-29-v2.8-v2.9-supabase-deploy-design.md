**Date:** 2026-04-29  
**Scope:** Mission Alive — auth, full DB migration, deployment, error tracking  
**Status:** Approved

## 1. Auth Flow

- **Method:** Supabase Auth — email + password
- **No public sign-up** — accounts created manually in Supabase dashboard (research participants)
- **Password reset:** `supabase.auth.resetPasswordForEmail(email)` → email link
- **Session storage:** Supabase JS v2 stores session in `localStorage` automatically; token auto-refreshed before expiry
- **App routing:** `loading → <Spinner>` | `no session → <LoginScreen>` | `session → <Landing> → <Session> → <Report>`

---

## 2. WebSocket Auth — First-Message Handshake

```
connect wss://…/ws/session
→ client sends  {"type": "auth", "token": "<access_token>"}
→ server validates JWT (PyJWT + SUPABASE_JWT_SECRET), extracts user_id
→ server sends   {"type": "auth_ok"}
→ normal 1Hz session loop begins
```

- On reconnect: call `supabase.auth.getSession()` again — always returns fresh token
- Invalid/missing token: server closes WS with code 1008, no session created

### RLS Policy (all tables)
```sql
-- Backend uses service-role key (bypasses RLS — server writes)
-- Frontend uses anon key (RLS enforced — users see only own rows)
alter table <table> enable row level security;
create policy "own data" on <table>
  using (auth.uid() = user_id)
  with check (auth.uid() = user_id);
-- profiles uses id instead of user_id
create policy "own data" on profiles using (auth.uid() = id) with check (auth.uid() = id);
```

### Indexes
```sql
create index on sessions(user_id, started_at desc);
create index on hrv_snapshots(session_id, epoch_s);
create index on rr_intervals(session_id, ts);
create index on session_events(session_id, ts);
create index on rf_calibration(user_id, measured_at desc);
```

### Auto-create profile on signup
Supabase SQL trigger (run once in dashboard):
```sql
create or replace function handle_new_user()
returns trigger as $$
begin
  insert into public.profiles (id) values (new.id);
  return new;
end;
$$ language plpgsql security definer;

create trigger on_auth_user_created
  after insert on auth.users
  for each row execute procedure handle_new_user();
```

### GDPR
`on delete cascade` on all foreign keys → deleting `auth.users` row wipes all user data.

## 4. Backend Integration

### New files
- `backend/auth.py` — `validate_token(token) -> dict` using PyJWT + SUPABASE_JWT_SECRET; raises `AuthError` on failure (WS handler catches → `close(1008)`)
- `backend/db.py` — asyncpg connection pool; exposes:
  - `get_pool()` — startup singleton
  - `create_session(user_id, session_type, mode, device_label) -> session_id`
  - `write_snapshot(session_id, user_id, epoch_s, metrics: dict)`
  - `write_rr(session_id, user_id, ts, rr_ms, accepted, source)`
  - `write_event(session_id, user_id, epoch_s, event_type, payload)`
  - `finish_session(session_id, outcome: dict)`

### Modified files
- `backend/main.py` — WS handler: auth handshake before session loop; `sentry_sdk.set_user({"id": user_id})` after auth; all DB writes via `db.py`
- `backend/requirements.txt` — add: `asyncpg`, `PyJWT`, `sentry-sdk[fastapi]`

### Sentry (backend)
```python
sentry_sdk.init(
    dsn=SENTRY_DSN,
    environment=ENVIRONMENT,
    traces_sample_rate=0.2,
    integrations=[FastApiIntegration(), AsyncPGIntegration()]
)
```
WS session loop `except` block: `sentry_sdk.capture_exception(e)`.

### Environment variables (Railway)
```
SUPABASE_URL
SUPABASE_SERVICE_ROLE_KEY
SUPABASE_JWT_SECRET
DATABASE_URL                  # postgres://… Supabase connection pooler (port 6543)
SENTRY_DSN
ENVIRONMENT=production
```

## 5. Frontend Integration

### New files
- `frontend/src/lib/supabase.js` — `createClient(VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY)`
- `frontend/src/lib/sentry.js` — `Sentry.init(dsn, { integrations: [browserTracingIntegration()], tracesSampleRate: 0.2 })`
- `frontend/src/pages/LoginScreen.jsx` — email + password form; forgot password link; no sign-up
- `frontend/src/context/AuthContext.jsx` — `supabase.auth.onAuthStateChange` → `{user, session, loading}` context

### Modified files
- `frontend/src/App.jsx` — route on auth state: loading → Spinner, no user → LoginScreen, user → existing flow
- `frontend/src/pages/Session.jsx` — WS auth handshake: `getSession()` → send `{type:"auth",token}` → wait for `auth_ok`
- `frontend/src/main.jsx` — init Sentry before rendering; wrap `<App>` in `<Sentry.ErrorBoundary>`

### Environment variables (Vercel)
```
VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
VITE_API_URL              # Railway backend HTTPS URL
VITE_SENTRY_DSN
```

### Sentry (frontend)
- `Sentry.setUser({ id: user.id, email: user.email })` on login
- `Sentry.setUser(null)` on logout
- Errors link to backend via Sentry trace IDs

## 6. Deployment

### Railway (backend)
```toml
[build]
builder = "NIXPACKS"

[deploy]
startCommand = "uvicorn backend.main:app --host 0.0.0.0 --port $PORT"
healthcheckPath = "/health"
healthcheckTimeout = 30
restartPolicyType = "ON_FAILURE"
```
Railway provides HTTPS automatically → BLE works on Android/iOS.

### Vercel (frontend)
```json
{ "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
```
Git push to main → auto-deploy. HTTPS enforced.

### Sentry projects
- `mission-alive-backend` → DSN → Railway env var
- `mission-alive-frontend` → DSN → Vercel env var
- Link projects in Sentry for cross-stack trace correlation

## 7. Smoke Test Checklist (post-deploy)

```
□ https://your-app.vercel.app loads on Android + iOS
□ Login with email+password succeeds
□ Invalid password shows error message
□ Forgot password sends email
□ WS connects → auth_ok received in < 2s
□ Simulator session runs 60s, VS score updates in UI
□ Session row appears in Supabase Table Editor (sessions table)
□ HRV snapshots appear (hrv_snapshots table, ~60 rows)
□ Session end → skill_transfer_score written
□ RLS check: user A cannot query user B's sessions (test via Supabase SQL editor)
□ Sentry receives test error (throw manually, verify in dashboard)
□ BLE scan appears on Android Chrome (confirms HTTPS)
□ BLE scan appears on iOS Safari (confirms HTTPS)
□ Railway health endpoint returns 200: GET /health
□ Token refresh: wait 1h, reconnect WS, session works
```
